
# CONTRIBUTING.md

## Задачи

- У каждой задачи должен быть назначен исполнитель и указан понятный критерий готовности.
- Если за 48 часов до срока сдачи практики по задаче нет открытого PR, другой участник может взять её на себя, предварительно сообщив об этом в Issue.
- Перед началом работы исполнитель проверяет актуальность требований и связанных задач.

## Ветки

Ветка создаётся от актуального `main`. Одна ветка — одна задача.

Новые ветки создаются с начальным индексом в зависимости от задачи:

    - feat/... - будущий функционал или задача;
    - fix/... - исправление бага;
    - docs/... - написание документации.

Имена веток должны состоять из строчных латинских букв, цифр и дефисов.

Работа непосредственно в `main` запрещена.

## Коммиты

- Сообщения коммитов пишутся на русском языке.
- Первая строка сообщения должна содержать не более 72 символов.
- Один коммит — одно логически завершённое изменение.
- Сообщения должны отражать суть внесённых изменений.

## Pull Request

- Все изменения в `main` вносятся исключительно через Pull Request.
- Прямой push и force push в `main` запрещены.
- В описании PR необходимо указать, что было сделано, зачем нужны изменения и ссылку на соответствующую Issue.
- Один PR должен решать одну задачу.
- Для слияния требуется одобрение хотя бы одного другого участника команды.
- После одобрения PR автор может выполнить слияние с `main`.
- После успешного слияния рабочая ветка удаляется.

## Review

- Для каждого PR назначается участник, который не является его автором.
- Ревьюер проверяет, соответствует ли реализация требованиям Issue.
- Проверяется корректность обработки файлов, включая неподдерживаемые форматы, пустые и повреждённые документы.
- Для конвертеров проверяется корректность выходных данных.
- Для изменений жизненного цикла Job проверяется допустимость переходов между состояниями.
- При добавлении функциональности проверяется наличие соответствующих тестов.
- Замечания должны быть содержательными: вопрос, обнаруженная проблема или предложение по улучшению с объяснением.
- Автор PR должен ответить на замечания: исправить проблему или аргументировать своё решение.
- После устранения замечаний ревьюер повторно проверяет изменения и принимает решение об одобрении PR.

## Definition of Done

Задача считается выполненной, когда:

- [ ] Выполнены все критерии приёмки, указанные в Issue.
- [ ] Изменения соответствуют требованиям проекта.
- [ ] Изменения отправлены через Pull Request.
- [ ] PR получил одобрение хотя бы одного другого участника команды.
- [ ] PR успешно объединён с `main`.
- [ ] Для программного кода добавлены тесты на корректную работу и хотя бы один ошибочный сценарий.
- [ ] Все существующие тесты проходят успешно.
- [ ] В репозитории отсутствуют пароли, токены и другие секретные данные.
- [ ] Конфигурационные параметры, если они необходимы, не зашиты непосредственно в исходный код.
- [ ] При изменении поведения системы обновлена соответствующая документация.
- [ ] Связанная Issue закрыта.
