# ADR-0001: Один процесс приложения

- Дата: 2026-11-13
- Статус: Принято

## Контекст и ограничения

Проект — учебный конвейер обработки документов. В текущей версии небольшой набор локальных Tools; эксплуатационные требования к независимому масштабированию частей системы не заданы. Команда должна минимизировать инфраструктурную сложность.

## Решение

Реализовать API, Dispatcher, Registry и локальные Tools в одном приложении/процессе. Границы компонентов сохраняются интерфейсами, чтобы при необходимости вынести части отдельно.

## Альтернативы

1. Микросервисы для API, Dispatcher и каждого Tool — независимое масштабирование, но больше сетевых отказов и инфраструктуры.
2. Отдельный сервис на каждый тип обработки — избыточно для текущего числа операций.

## Цена решения

- Плюсы: простой запуск, отладка и локальная разработка.
- Минусы: общий жизненный цикл процесса; сбой процесса затрагивает весь конвейер; масштабирование отдельных Tools невозможно независимо.

## Условия пересмотра

Пересмотреть ADR, если появится высокая нагрузка, независимые требования к масштабированию Tools, разные требования к безопасности или необходимость отдельного релиза компонентов.
