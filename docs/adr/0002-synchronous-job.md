# ADR-0002: Синхронное выполнение Job в первой версии

- Дата: 2026-11-13
- Статус: Принято

## Контекст и ограничения

Учебная версия выполняет ограниченный набор локальных операций над документами. Очередь сообщений и отдельные worker-процессы увеличили бы объём инфраструктуры. При этом API должен явно фиксировать жизненный цикл Job.

## Решение

В первой версии Dispatcher выполняет Job синхронно в рамках запроса. Job проходит `created → running → succeeded|failed`. Состояния и API спроектированы так, чтобы позже добавить очередь и `queued`. Отмена не поддерживается.

## Альтернативы

1. Фоновая очередь и worker — лучше для долгих задач, но требует брокера, повторной доставки и восстановления после перезапуска.
2. Отдельный процесс на каждую Job — простая изоляция, но дорогой запуск и сложнее управление ресурсами.

## Цена решения

- Плюсы: меньше компонентов, проще тестирование.
- Минусы: долгие запросы могут завершаться таймаутом клиента; перезапуск процесса прерывает выполняемую операцию; нет отмены и автоматического повтора.

## Условия пересмотра

Пересмотреть, если типичное время обработки превышает допустимый HTTP timeout, появится высокая параллельная нагрузка, необходимость отмены, гарантированного восстановления или повторного выполнения.
