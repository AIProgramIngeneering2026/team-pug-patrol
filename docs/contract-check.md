# Проверка контракта колодой К1–К10

| Карта | Ответ контракта |
|---|---|
| К1 Двойной клик | `POST /jobs` требует `Idempotency-Key`; повтор с тем же ключом и тем же телом возвращает `200` и прежний Job. `docs/api/openapi.yaml`, `POST /jobs`. |
| К2 Ответ потерялся | Клиент повторяет запрос с тем же `Idempotency-Key` и получает прежний Job (`200`); новый Job не создаётся. `docs/api/openapi.yaml`, `POST /jobs`. |
| К3 Неизвестная операция | Enum `operations` ограничивает допустимые значения; неизвестное значение отклоняется с `400`, `INVALID_INPUT`, поле `operations`. Job не создаётся. `docs/api/openapi.yaml`, `CreateJobRequest`. |
| К4 Кривые параметры | Отсутствующие поля, неверные типы и дополнительные поля отклоняются с `400`; тело `Error` указывает `field`. `docs/api/openapi.yaml`, `CreateJobRequest`, `Error`. |
| К5 Воскрешение | Терминальные `succeeded` и `failed` не запускаются повторно: `409 INVALID_STATE_TRANSITION`. Для новой попытки создаётся новый Job с новым ключом. `docs/job-state.md`. |
| К6 Отмена | Сознательно не поддерживается в первой версии: `DELETE /jobs/{jobId}` отвечает `409 OPERATION_NOT_SUPPORTED`. Причина — синхронное выполнение и отсутствие безопасной модели частичной отмены; `docs/adr/0002-synchronous-job.md`. |
| К7 Огромный вход | Файлы больше 50 MiB отклоняются с `413 PAYLOAD_TOO_LARGE`; файл не обрабатывается. `docs/api/openapi.yaml`, `PayloadTooLarge`. |
| К8 Чужой или несуществующий id | Для отсутствующего или недоступного текущему клиенту Job возвращается одинаковый `404 NOT_FOUND`, чтобы не раскрывать существование чужого Job. `docs/api/openapi.yaml`, `GET /jobs/{jobId}`. |
| К9 Перезапуск сервера | В синхронной версии выполняющаяся операция может прерваться; после рестарта незавершённая Job считается `failed` при восстановлении из Repository. Автоматического повтора нет; это ограничение описано в `docs/adr/0002-synchronous-job.md`. |
| К10 Внешний сервис | Внешние OCR/перевод/LLM не вызываются в этой версии. Для будущей интеграции предусмотрены Port и Adapter; таймаут и некорректный ответ адаптера должны преобразовываться в `TOOL_TIMEOUT` или `TOOL_INTERNAL_ERROR`. `docs/architecture.md`, `docs/tool-contract.md`. |

## Что предложил ИИ

### Промпт атакующего

> Ты — атакующий ревьюер API-контракта конвейера обработки документов. Изучи OpenAPI, диаграмму состояний, Tool-контракт, ADR и таблицу К1–К10. Найди ещё три опасные ситуации, не совпадающие с картами колоды. Для каждой опиши сценарий, последствия и конкретное изменение контракта.

### Дополнительные ситуации

1. **Одинаковый Idempotency-Key с разным телом.** Принято: добавить правило — повтор ключа с идентичным телом возвращает прежний Job; с отличающимся телом возвращает `409 IDEMPOTENCY_KEY_REUSED`. Это уточнение должно быть реализовано в обработчике `POST /jobs`.
2. **Доступ к файлу по подменённому `fileId`.** Принято: проверять принадлежность файла текущему клиенту до создания Job; при отсутствии доступа возвращать `404`, не раскрывая владельца. Это правило добавлено в описание `CreateJobRequest` и проверки входного слоя.
3. **Два параллельных запроса с одним ключом.** Принято: уникальность `(client_id, Idempotency-Key)` обеспечивается атомарно в Job Repository; проигравший запрос читает и возвращает уже созданный Job. При конфликте разных тел — `409 IDEMPOTENCY_KEY_REUSED`.

## Ограничения и уточнения контракта

- `client_id` определяется механизмом аутентификации; конкретная схема аутентификации зависит от инфраструктуры курса и не задана исходным заданием.
- Хранение файлов и Job Repository должны обеспечивать проверку владельца. Реализация БД/объектного хранилища не предписывается.
- Для `POST /jobs` требуется сохранять хеш тела запроса вместе с ключом идемпотентности.
